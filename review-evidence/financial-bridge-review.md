# Representative financial Feature bridge

The approved representative is GRC004, TTM revenue year-over-year, using native `financial_events.revenue` in cumulative YTD CNY. Data owns revision choice and single-quarter/TTM arithmetic. Research selects the latest visible economic report period and the period four fiscal quarters earlier; the existing Core divide/subtract recipe computes the Feature. Missing quarters and withdrawals remain null. This is one representative, not completion of the remaining financial catalog.

The public `extend_financial_feature_source` accepts a pinned independent `event_snapshot`, one EventQuery, and explicit output derivation/quarter-offset declarations. It preserves the market source's Snapshot and original buffer descriptors. Financial coverage is explicit; unsupported securities are rejected rather than counted as calculated null cells. A subset request uses the existing Engine `select_security_plan` followed by `FeatureRequest`/`FeatureLibrary.ensure_features`; the Catalog convenience wrapper remains available when the complete physical source is covered.

At each session the event cutoff is the earlier of the original decision cutoff and local session midnight minus one microsecond, matching the reviewed strict-before disclosure convention. This version accepts best_effort_vendor_v1 only. Each cell retains current/target report periods, query cutoff, Data component statuses, revisions and availability bases, with maximum component availability. Precise financial missing reasons remain in immutable evidence; the existing packed reason dictionary uses source_missing for these input nulls. Derived source profiles explicitly identify report materialization and bind its mathematical interpretation, without putting a Snapshot or coverage axis into mathematical identity.

The new Data `iter_event_cutoffs` helper shares a pinned manifest, public evidence and partition table cache for at most 32 cutoffs and 256 securities. It calls the original read_events selector for every cutoff. It reserves a conservative bounded cache before each partition read, checks actual table size, revalidates partition bytes on cache hits and checks the Snapshot epoch around selection. There is no new revision selector. Initial Arrow decode is not a hard RSS bound; each block still admits its small event manifest, and global-history scaling has not been measured. Research performs each requested financial derivation once over the union of current/prior-year target periods per selected batch.

Validation is synthetic and uses actual Data Parquet/event selection, Data TTM, saved source admission and the installed GRC004 catalog. Three bridge tests verify same-day revision delay, withdrawal, missing-quarter propagation, current/prior-year alignment, explicit partial security coverage, immutable component evidence and repeated subset with zero Core calculations. One partition read serves six cutoffs and both output leaves. Two Data tests compare exact batches against original read_events and check budget/epoch failure. The directly affected bridge/daily-source/library set passed nine tests. No supplier reads, large preparation, model run or real historical scalability claim occurred in this subtask; the input owner performs the separately approved one-security real example.
